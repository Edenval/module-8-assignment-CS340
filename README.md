# CS 340 Module Eight Journal

When I write code I try to keep it organized and easy to understand, especially if I need to go back and change something later. I think using clear names, keeping functions separate, and adding comments when necessary makes a big difference. In Project One, I created a CRUD Python module to handle the database operations instead of putting everything directly into the dashboard. This was helpful in Project Two because I could use the same module to connect to MongoDB and retrieve the animal records. I also found it easier to figure out where problems were coming from since the database functions and dashboard code were not mixed together. Another benefit is that I could reuse the module for other projects without having to start over. For example, I could use a similar approach for an inventory system or another application that needs to store and retrieve information.

When working on a programming assignment, I usually start by looking at what is required and figuring out how to complete each part. For the Grazioso Salvare project, I needed to create a dashboard that allowed users to filter animal records and view the results through a table, chart, and map. I worked on each feature separately and tested it to make sure it behaved the way I expected. This project was a little different from previous assignments because I had to think more about how everything worked together rather than just getting the code to run. For example, changing a filter needed to update the information displayed in the dashboard, not just the table. I also had to consider whether the dashboard would actually be useful for someone trying to find animals that met specific rescue requirements. In future projects, I would approach things in a similar way by understanding what the client needs, organizing the work into smaller parts, and checking that everything works properly before moving on.

I think computer scientists are problem solvers who use technology to make certain tasks easier or more efficient. A lot of the work involves figuring out how to handle information in a way that is useful to other people. In the case of Grazioso Salvare, the dashboard could help employees find animals that meet the requirements for different types of rescue training without having to search through the database manually. They can apply filters and see the matching records along with charts and location information. This makes it easier to compare results and find what they are looking for. What I liked about this project is that it showed how something we build in class could have a practical use outside of school. It also helped me understand why it is important to think about the person using the program and not only whether the code works.
